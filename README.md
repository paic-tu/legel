# مكتب متابعة الإدارة القانونية

تطبيق ويب عربي متجاوب لتنظيم أعمال الإدارة القانونية، من التسجيل والتوجيه إلى التنفيذ والمراجعة والإغلاق. جميع المؤشرات والتقارير محسوبة من البيانات المحفوظة وليست أرقاماً ثابتة في الواجهة.

## وضع البيانات

يستخدم التطبيق Supabase وحده بمصادقة وصلاحيات على الخادم. أُلغي التخزين المحلي والوضع التجريبي؛ لا يُحمّل التطبيق بيانات بديلة عند فشل الاتصال.

**تم تفعيل قاعدة البيانات وحسابات الدخول:** نُشر الترحيلان وأُنشئت الحسابات السبعة وربطت بأدوارها، ونجح الدخول والاتصال بالقاعدة فعلياً. حساب المدير `legal.manager@thabat.sa`، وكلمة المرور هي المطلوبة من المستخدم دون حفظها في الملفات. راجع [حالة إعداد Supabase](SUPABASE_SETUP.md) لنطاق التنفيذ وحدود النشر العام والبريد.

إعدادات اتصال المشروع العامة مضمنة كقيم افتراضية للنشر، فلا يعتمد بناء GitHub على وجود `.env.local`. يمكن تجاوزها بمتغيرات `.env.example` عند الاتصال بمشروع آخر؛ أعد البناء بعد تغييرها في منصة النشر. لا تضع مفتاحاً إدارياً في متغيرات `VITE_*`. تعريف الحسابات السبعة على `@thabat.sa` وآلية دعوتها في `supabase/team.json` و`supabase/provision-team.mjs`. راجع [قرارات التنفيذ](IMPLEMENTATION_DECISIONS.md) للحالة الفعلية والافتراضات.

## التشغيل

المتطلبات: Node.js 20.19 أو أحدث وnpm. يوصى بالإصدار 22 أو 24.

```powershell
npm ci
npm run dev
```

افتح `http://localhost:5173`. إذا كان المنفذ مستخدماً، يعرض Vite المنفذ البديل في الطرفية.

```powershell
npm run build
npm run preview
```

الناتج القابل للنشر في `dist`. يمكن تقديمه عبر أي خادم ملفات ثابتة مع HTTPS. لا تفتح `index.html` مباشرة بصيغة `file://`.

## الاستخدام

1. يبدأ المكتب دون معاملات تجريبية، بسجل الفريق المعتمد بعد نشر الترحيلات وربط حساباتهم، وبالتاريخ الفعلي من الخادم.
2. يسجّل المدير المعاملة ويحدد جهة الإحالة والمكلّف وضابط الاتصال والمهلة وصيغة التسليم. معاينة الرقم لا تحجزه؛ يُصدر داخل عملية الحفظ الذرّية.
3. اضغط أي معاملة لفتح تفاصيلها. يسجّل المكلّف الإجراءات ويرفع الناتج للمراجعة؛ يستطيع ضابط الاتصال إعادة إسناد المعاملة الموجهة إليه وبدء تنفيذها.
4. المدير وحده يعدّل المهل والمبالغ وضابط الاتصال، ويعتمد الإغلاق من مرحلة «قيد المراجعة» فقط.
5. يستخدم كل موظف حساب دخوله المرتبط، ولا يمكنه تبديل هويته. المكلّف يرى المسند إليه فقط، وضابط الاتصال يرى الموجه إليه أو المسند إليه.
6. اضغط خلايا الأولوية أو مراحل العمل أو مؤشرات اللوحة لفتح السجل مصفّى. السجل قابل للبحث والترتيب وترقيم الصفحات.
7. اختر فترة التقرير ثم صدّره إلى Excel أو استخدم «طباعة / PDF». التقارير العامة للمدير فقط.
8. `Ctrl+K` يفتح البحث السريع، و`Escape` يغلق النافذة الأعلى. يدعم التطبيق الوضع الداكن وتفضيل تقليل الحركة.

## المعمارية

| الطبقة | الملفات | المسؤولية |
|---|---|---|
| المنطق المستقل | `src/domain.ts` | أيام العمل، الأولوية، الحالة المشتقة، الترقيم، التحقق، الصلاحيات، المؤشرات والتقارير |
| البيانات المرجعية | `supabase/team.json` و`supabase/migrations` | تعريف الفريق والقوائم والمهل على الخادم |
| المستودع | `src/repository.ts` | واجهة `LegalRepository` وتوجيه حصري إلى Supabase |
| المستودع السحابي | `src/supabaseRepository.ts` | تحميل البيانات والكتابة عبر RPC دون إرسال هوية المنفّذ |
| المصادقة | `src/supabase.ts` و`src/AuthScreen.tsx` | الجلسة والدخول والاستعادة والخروج |
| قاعدة البيانات | `supabase/migrations` | RLS وRPC والترقيم والتدقيق والقوائم والتفضيلات وقواعد العمل الخادمة |
| الحالة | `src/store.ts` | Zustand، التصفية والتصفح والإشعارات والاشتراك الحي |
| Excel | `src/excel.ts` | التصدير والمعاينة والتحقق وكشف التكرار وتقارير الأخطاء |
| الواجهات | `src/App.tsx` والصفحات | عرض RTL والتسجيل والمتابعة والإعدادات |
| نظام التصميم | `src/styles.css` | الرموز اللونية، الحالات، الحركة، التجاوب والطباعة |

التقنيات: React 18 وTypeScript وVite وTailwind CSS وZustand وdate-fns وSupabase وSheetJS. الرسوم مخصصة باستخدام CSS وSVG، والأيقونات متجهة. ملفات IBM Plex Sans Arabic وIBM Plex Mono مجمّعة محلياً عبر Fontsource؛ لا طلبات خطوط إلى CDN وقت التشغيل.

يقرأ `legal_load` المعاملات المسموحة والقوائم والإعدادات وتفضيل العرض من PostgreSQL. تمر عمليات الكتابة عبر `legal_execute` بهوية من `auth.uid()`. الترقيم والتعديلات ذرية على الخادم. جلسة الدخول التقنية وحدها محفوظة بواسطة Supabase SDK؛ بيانات المكتب لا تُحفظ في تخزين المتصفح.

يستخدم التطبيق `SupabaseRepository` خلف واجهة `LegalRepository`. لا يرتبط منطق الصفحات بتفاصيل التخزين. يحدث البيانات كل 30 ثانية وبعد العمليات؛ لا يوجد رفع تلقائي للبيانات المحلية السابقة أو تشغيل دون اتصال.

## قواعد الحساب والقرارات

- المهل بأيام العمل، مع استثناء الجمعة والسبت. يبدأ العد من اليوم التالي للاستلام، والعاجل `min(المعيارية, 2)`.
- التأخر بالأيام التقويمية. يوم آخر موعد ليس متأخراً، والاستحقاق القريب يشمل اليوم وثلاثة أيام تالية، ولا يشمل المتأخرات أو المغلق.
- الموعد النظامي اليدوي يتقدم على المقترح. لا يتغير الموعد اليدوي عند تعديل النوع أو الاستعجال إلا عند طلب استخدام المقترح.
- المهلة المعيارية الفعلية محفوظة داخل المعاملة؛ تغيير إعدادات النوع لا يعدّل المعاملات القديمة.
- تاريخ الاستلام والإغلاق `yyyy-MM-dd`. يُصدر الخادم التاريخ وفق الرياض والوقت وهوية المنفّذ، ويعيد التاريخ المرجعي للمؤشرات. تفعيل العرض التجريبي مرفوض في القاعدة.
- نسبة الالتزام مقربة إلى أقرب عدد صحيح. الفترة دون إنجاز تعرض «لا يوجد إنجاز» ولا تُفسّر على أنها 100%.
- متوسط الإنجاز بالأيام التقويمية، ويُعرض لكل نوع في التقرير. المتراكم هو وارد الفترة ناقص منجزها.
- المدير لا يدخل في مؤشر «منسوبو الإدارة». يظهر في تقرير المكلّفين إذا أُسندت إليه معاملات.
- إزالة المنسوب تعني أرشفته مع إبقاء اسمه في البيانات التاريخية. تمنع إزالة أي منسوب مرتبط بمعاملة مفتوحة كمكلّف أو ضابط اتصال.
- لا يسمح بتعديل المعاملة المغلقة أو حذف سجلها من عمليات التطبيق.

## Excel

التصدير بورقتين «المعاملات» و«المنسوبون» مع اتجاه RTL وعناوين عربية وعروض أعمدة مناسبة. التقرير بورقات للملخص والنوع والمكلّف والمتأخرات والملاحظات الآلية.

الأعمدة المعتمدة:

`رقم المعاملة، النوع، الموضوع، جهة الإحالة، الطرف الآخر، ضابط الاتصال، المكلف، مهم، عاجل، تاريخ الاستلام، آخر موعد، المرحلة، تاريخ الإغلاق، المبلغ، صيغة التسليم، الوصف`.

يضيف التصدير عمودين اختياريين: «المهلة المعيارية» و«سجل الإجراءات» للحفاظ على التفاصيل في جولة التصدير والاستيراد. يُحفظ السجل بصيغة JSON داخل خلية.

- يقبل النوع باسمه العربي الكامل أو رمزه، والموظف باسمه المطابق أو معرفه.
- يقبل «مهم» و«عاجل» بقيم نعم/لا أو 1/0، والتاريخ نصاً `yyyy-MM-dd` أو تاريخ Excel رقمياً.
- يجب إضافة المنسوبين غير الموجودين في الإعدادات قبل الاستيراد. ورقة المنسوبين للتصدير والمرجعية، ولا تُنشئ مستخدمين تلقائياً.
- المعاينة تعرض نتيجة كل صف، والأرقام المكررة في الملف أو البيانات الحالية. يُعتمد الصالح غير المكرر فقط.
- يمكن تنزيل قالب فارغ وتقرير أخطاء. الحد الأقصى 5 ميجابايت و10000 صف.
- تُضاف واقعة الاستيراد إلى سجل كل معاملة جديدة، ولا يغير استيراد الرقم المكرر المعاملة الحالية أو سجلها.
- يستخدم المشروع إصدار SheetJS 0.20.3 من مصدره الرسمي بدلاً من إصدار npm القديم المتأثر بثغرات معروفة. هذا تنزيل وقت التثبيت فقط.

## الحدود التشغيلية والأمان

التطبيق الحالي لا يقرأ التخزين المحلي السابق ولا يحذفه. تحفظ المعاملات والإعدادات في مشروع Supabase؛ يجب إعداد النسخ الاحتياطية والاستعادة من جهة التشغيل.

في Supabase الهوية من Authentication والصلاحيات من RLS وRPC. الكتابة المباشرة للجداول ممنوعة على مستخدمي التطبيق، والرقم والمهلة والتواريخ والتدقيق تُفرض على الخادم. الحساب غير المرتبط بموظف نشط لا يصل إلى بيانات المكتب، وأرشفة الموظف تلغي وصوله حتى مع جلسة باقية. لا تُرسل الواجهة هوية المنفّذ ولا تستخدم مفتاحاً سرياً.

يبقى الاعتماد الإنتاجي مشروطاً بالنشر الفعلي واختبار الحسابات ومراجعة الأمان والنسخ الاحتياطية والاستعادة والمراقبة. مسؤول قاعدة البيانات يملك صلاحيات أعلى من المستخدمين، فلا يُدّعى تحصين السجل ضده. لا يوجد رفع ملفات وثائق أو تخزين مرفقات لأن الحقول المطلوبة اقتصرت على الوصف.
